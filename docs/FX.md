# FX — сочность основного процесса боя (этапы FX-0…FX-9)

Цель — сделать отправку войск, удары по узлам и захват «вкусными» на ощупь. **Правила игры не меняются**: всё в этом документе — отображение, звук и тактильный отклик. Единственная правка `src/core/` — счётчик выпусков у узла (FX-3), без влияния на симуляцию.

Решения приняты по интерактивным прототипам вместе с пользователем (2026-11-08). Числа ниже взяты из прототипов: это стартовые значения, все — в конфиге и подбираются по ощущению.

## Правила
- Каждый этап — **отдельный коммит** (сообщение на английском, префикс `feat(fx):`), после каждого `npm run lint && npm run test && npm run build`.
- **Производительность — приоритет №1** (CLAUDE.md №7, `ARCHITECTURE.md` → «Производительность»). В бою: никаких `new`/`scene.add.*`/твинов на юнита или на частый эффект (удар, выпуск); всё из пулов, созданных при загрузке боя или в `BootScene`. Редкие события (захват, победа) — тоже из пулов, если это не сложнее; создание объектов в бою допустимо только там, где оно уже есть сейчас (`pop`, `ringBurst`).
- После каждого этапа — `npm run profile` (`dev_stress` и `c01_l06`, CPU ×6) и сравнение с замером FX-0. Если этап заметно ухудшил p95 кадра — сначала оптимизировать, потом идти дальше. Результаты — в таблицу внизу.
- Все новые числа — в `src/config/game.ts` (визуальные константы, рядом с `UNITS_FX`, `HAPTICS`), не в `balance.ts`. Магических чисел в коде нет.
- Новых строк интерфейса нет (i18n не трогается).
- Размеры — через `px()` и от радиуса узла / масштаба поля, проверять в портрете 360×640 и альбоме 1280×720.
- Если по визуалу что-то неясно или есть выбор, меняющий внешний вид, — спросить, а не решать самому. Не добавлять эффектов сверх описанных.

## Что уже есть (использовать, не дублировать)
- `effects.ts`: `pop` (твин масштаба узла до 1.18), `ringBurst` (одно кольцо), `sparks` (Graphics на каждую частицу — **в бою не использовать**).
- `FlashPool` в `UnitsView.ts` — вспышки касаний и выстрелов башен с потолком и лимитом на точку. Образец для новых пулов.
- `BattleScene.showCapture(view)` — вызывается, когда узел **показал** нового владельца (`DisplayFilter`, PLAYTEST-1 F-2: перезахват чаще 0.3 с не показывается вовсе). Все эффекты захвата вешать сюда, а не на событие симуляции.
- `BattleScene.shake()` и `HAPTICS.shakeMs/shakeIntensity` — сейчас тряска только при захвате вражеской столицы и от огненного шара.
- `runClock` + `battleSpeed` (`core/sim/clock.ts`) — скорость симуляции читается перед каждым тиком; `SLOW_MO` уже замедляет бой на время выбора.
- `perfFlag` (`src/dev/perfFlags.ts`) — dev-флаги в URL.
- `UnitsView` — все юниты одним `Blitter`, позиции без памяти о прошлом тике. Важно: **`Bob` не масштабируется и не вращается** — анимацию формы делать сменой кадра атласа.

## Итог решений (что делаем и чего не делаем)
| Момент | Делаем | Не делаем |
|---|---|---|
| Выпуск юнита | сжатие + белая вспышка узла-источника, 3 искры | — |
| Колонна | строго по дороге, одна полоса | след, разброс, полосы (полосы — вместе с апгрейдом ширины колонны, позже) |
| Юнит в пути | шаг (подпрыгивание + кадры сплющивания), пыль из-под ног | — |
| Удар по узлу | сжатие + вспышка, число подпрыгивает, частицы цвета атакующего; свой узел ещё и дрожит | — |
| Поток сорван атакой | красное пунктирное вращающееся кольцо | автопродолжение потока (правило GDD §3.6 остаётся: поток отменяется) |
| Захват игроком | волна перекраски круга от стороны удара, два кольца, конфетти, тряска, короткий стоп-кадр 0.2 с | флаг, надпись «+1 узел», зоны территории |
| Захват врагом / нейтральный узел врагом | как сейчас (`pop`, кольцо, звук) | тряска, стоп-кадр |
| Узлы в покое | «дыхание» | свечение своих узлов |
| Победа | волна по полю перед экраном результата | звёзды на поле (они уже есть на экране результата) |
| Звук | существующие `send`, `capture`, `clash` | новые звуки (шаг, частицы) |
| Фон | — | птицы — отдельной задачей позже |

## FX-0. Подготовка и замер «до»
- `npm run profile` на `dev_stress` и `c01_l06` (портрет и альбом) — записать в таблицу «до» внизу.
- Dev-флаг `?perf=nofx` (добавить в `PerfFlag`): выключает **все** эффекты этого документа — для A/B-замеров и сравнения на глаз. Каждый следующий этап обязан его уважать.
- Добавить в `game.ts` объект `FX` (или несколько: `NODE_FX`, `STEP_FX`, `DUST_FX`, `CAPTURE_FX`, `VICTORY_FX`) — по мере этапов.
- **Готово, когда:** есть таблица «до», флаг заведён (пока ничего не выключает).

## FX-1. Внутренний слой узла и «дыхание»
- В `NodeView` выделить **внутренний слой** (тело `bodyArt.image` + дуга `cap.image`), которому даются масштаб/смещение эффектов. Контейнер узла целиком по-прежнему двигает `pop()` — эффекты слоя и `pop` не должны перетирать друг друга (вложенный `Container` или масштаб, выставляемый вручную обоим изображениям; выбрать по замеру, вложенный контейнер в Phaser 4 проверить на стоимость).
- Анимация слоя — **вручную в `update`/`sync` по времени сцены**, без твинов: одно число на узел.
- **Дыхание:** масштаб слоя `1 + 0.035 · sin(2 · t + phase)` (t — секунды, период ≈ 3.1 с), `phase` — случайная на узел при создании. Все стороны, включая нейтральных. Число узла не дышит (читаемость).
- **Готово, когда:** узлы дышат вразнобой; `pop` при захвате работает как раньше; в замере нет новых аллокаций в кадре.

## FX-2. Удар по узлу
Источник — событие `arrived` с `outcome` `repelled` или `destroyedByTower` (там уже есть `fromId` для направления; сейчас по нему рисуется `FlashPool`).
- **Сжатие + вспышка.** Импульс `punch = 1` на слое узла: масштаб `1 − 0.14 · punch`, `punch` гаснет линейно за 0.2 с. Белая вспышка поверх круга: заранее запечённый белый круг (одна текстура на размер раскладки, одна `Image` на узел, скрыта), альфа `0.8 · flash`, гаснет за ~0.17 с.
- **Число подпрыгивает:** масштаб `countText` `1 + 0.45 · pop`, гаснет за 0.25 с (масштаб `Text` не перерисовывает его текстуру — дёшево; если к этому моменту сделан PF-2 — масштабировать спрайты цифр).
- **Частицы цвета атакующего:** 6 штук из общего эмиттера искр (см. ниже), из точки на краю круга со стороны атакующего, конусом ±0.8 рад наружу, скорость ~170 px·(0.4…1.2), жизнь 0.35–0.6 с, размер 2–4 px, цвета — `faction` и светлый тон атакующей стороны.
  - Эмиттер искр — **один** `ParticleEmitter` Phaser 4 на сцену, создан в `create()`, текстура — маленький белый квадрат (запечь в `BootScene`), цвет — tint на всплеск, `maxParticles` с потолком (стартово 200). Сверить API эмиттера с Phaser 4.2.
  - Лимит: не чаще одного всплеска на узел в 100 мс (как `UNITS_FX.flashEverySpotMs`). Массовый штурм узла не должен давать сотни частиц.
- **Свой узел дрожит** (цель — узел игрока): смещение слоя ±3 px случайно каждый кадр, амплитуда гаснет за 0.3 с.
- Существующая вспышка `FlashPool` на краю узла — оставить или убрать, если вместе с частицами выглядит перегруженно: **показать пользователю оба варианта**.
- **Готово, когда:** на штурме виден каждый удар, `dev_stress` укладывается в бюджет, число частиц на экране не превышает потолок.

## FX-3. Выпуск юнита
- **Сигнал из симуляции без аллокаций:** в `NodeState` поле `released: number` — сколько юнитов узел выпустил за бой (+1 в `releaseStreams` на каждый `spawnUnit`, включая транзит и волны цитадели). Вид сравнивает с прошлым значением в `NodeView`. Тест Vitest: счётчик растёт ровно на число вышедших юнитов, на симуляцию не влияет (существующие тесты зелёные, `npm run bench` не хуже).
- На каждый выпуск: `punch = 1` слою узла-источника (как в FX-2), белая вспышка, **3 искры** светлого цвета своей стороны из точки на краю круга в сторону дороги, конус ±0.5 рад, скорость ~100 px, жизнь 0.3–0.6 с. Темп выпуска 5/с — импульсы будут накладываться, это нормально (берётся максимум, а не сумма).
- Только для узлов игрока (решено, см. «Открытые вопросы»).
- **Готово, когда:** колонна визуально «выстреливается» из узла; повторный свайп и транзит работают как раньше.

## FX-4. Шаг юнита
- **Подпрыгивание:** в `UnitsView.render` к `bob.y` добавить `−A · |sin(φ)|`, где `φ = π · s / stepLen + unit.id`, `s` — пройденное расстояние по дороге на экране (из того же прогресса, что и позиция — без памяти о прошлом кадре), `A = 2.4 px` (масштабировать от радиуса фигурки), `stepLen` — длина шага на экране: ≈ 4.5 шага в секунду при `ARMY.speed`.
- **Сплющивание:** `Bob` не масштабируется, поэтому в атлас фигурок (`UnitsView.layout`) запечь на каждую сторону **3 кадра**: обычный, вытянутый (×0.92 по ширине, ×1.12 по высоте), промежуточный. Кадр выбирается по `|sin(φ)|` (0…0.33 / 0.33…0.66 / 0.66…1). `setFrame` — только когда кадр сменился (хранить текущий кадр рядом с `bobOwner`).
- Следа нет, бокового разброса нет — юниты идут строго по линии дороги.
- **Готово, когда:** колонна читается как идущая пешком; `dev_stress` (600 юнитов) не хуже замера FX-0 больше чем на шум; draw call'ов столько же (одна текстура).

## FX-5. Пыль из-под ног
- Отдельный `Blitter` под юнитами с пулом облачков фиксированного размера (стартово **120**), текстура — 4 кадра облачка растущего размера (радиус 2 → 4.7 px от размера фигурки), цвет `#B4B2A9`. `Bob` без масштаба — рост облачка = смена кадра, угасание — `bob.alpha`.
- Юнит пускает облачко раз в 0.28–0.58 с (детерминированно от `unit.id` и пройденного пути, без памяти). Облачко: жизнь 0.45 с, альфа 0.6 → 0, сносится назад вдоль дороги ~14 px/с и вверх ~6 px/с.
- **Нагрузка:** если пул занят — облачко просто не появляется. Когда на поле больше `DUST_FX.fullUntilUnits` юнитов (стартово 150), пылит только каждый N-й юнит (`unit.id % N`), при `DUST_FX.offAboveUnits` (стартово 400) пыль выключается совсем.
- **Готово, когда:** на обычном уровне пыль видна у каждого юнита; на `dev_stress` она не съедает бюджет кадра.

## FX-6. Кольцо «поток сорван»
- Правило не меняется (GDD §3.6): атака на узел отменяет его поток, остаток остаётся в гарнизоне, сам поток не продолжается.
- Вид определяет срыв без правок симуляции: у узла игрока в прошлом кадре `node.streams > 0`, в этом `0` и `isAttacked(world, node)` → показать кольцо.
- Кольцо: запечённая текстура красного пунктира (`COLORS.faction.enemy`, толщина ~3 px, радиус `r + 8 px`), одна `Image` на узел, скрыта по умолчанию. Вращение ~1 оборот за 1.9 с, альфа пульсирует `0.55 + 0.45 · sin(t · 16.7)`. Держится, пока узел атакован (из него и так нельзя отправить), но не меньше 0.6 с, затем гаснет за 0.2 с.
- Только для узлов игрока.
- **Готово, когда:** при сорванной атаке кольцо видно сразу; при обычном завершении потока (все вышли) кольца нет.

## FX-7. Захват узла игроком
Всё — в `showCapture`, когда `owner === 'player'`. Захват врагом остаётся как сейчас.
- **Волна перекраски круга.** Круг перекрашивается не мгновенно, а волной за **0.5 с** (ease-out cubic) **со стороны, откуда пришёл захвативший юнит**: запомнить `fromId` последнего `arrived` с `outcome === 'captured'` по узлу (поле в `BattleScene`, без аллокаций в кадре — `Map` создаётся один раз). Реализация на выбор по стоимости: маска Phaser 4 (проверить цену) или наложение «линзы» (пересечение круга узла и растущего круга — два `arc` в одном `Graphics` из маленького пула, только на время волны). Наложение повторяет двухтоновую заливку узла (обод `factionDark` + лицо `faction`). Тело узла перепекается в нового владельца в конце волны. Иконки построек и корона могут быть перекрыты волной не дольше её длительности.
- **Два кольца** цвета игрока (светлый тон): первое — толщина 5 px, от радиуса узла до `r + 70 px` за 0.6 с; второе — с задержкой 0.12 с, толщина 3 px, до `r + 45 px`. Ease-out cubic, альфа 1 → 0. Из пула колец (запечённая текстура кольца, 4–6 `Image`), а не через `ringBurst`.
- **Конфетти:** отдельный эмиттер (создан в `create()`), 40 частиц, цвета: синий, светло-синий, янтарный, светло-янтарный, бирюзовый; скорость 240·(0.4…1.2) во все стороны, гравитация 320 px/с², вращение, жизнь 0.5–1.0 с, размер 2–5 px.
- `pop` и звук `capture` — как сейчас. Флага и «+1 узел» нет.
- **Готово, когда:** захват игроком ощущается главным событием боя; перезахваты чаще 0.3 с по-прежнему не показываются (`DisplayFilter`).

## FX-8. Тряска камеры и стоп-кадр
Решение «трясти/замедлять» — чистая функция без Phaser (например `src/core/fx/captureFeedback.ts`), покрыть тестами Vitest: на вход время, тип узла, когда игрок терял этот узел, когда были прошлые тряска/стоп-кадр, флаги «выбирает»/«обучение»/«бой окончен»; на выход — `{ shake: none | normal | capital, hitStop: boolean }`.
- **Тряска** — на каждом захвате игрока, включая перезахват своего потерянного узла:
  - обычный узел: ~300 мс, интенсивность ~0.006; столица врага: ~400 мс, ~0.01 (подобрать на глаз, ориентир — прототип: ±5 px, затухание ~0.45 с);
  - кулдаун **1 с** между тряскими (столица кулдаун игнорирует).
  - Огненный шар и дракон трясут как сейчас.
- **Стоп-кадр:** симуляция идёт на скорости `CAPTURE_FX.hitStopSpeed` (0.2) в течение **0.2 с реального времени**. Встроить в `battleSpeed` третьим аргументом (минимум из скоростей), таймер — в реальном времени сцены. Эффекты (кольца, конфетти, тряска) идут в реальном времени, замедляются только юниты и симуляция.
  - **Не срабатывает**, если: с прошлого стоп-кадра прошло меньше **3 с**; игрок потерял этот узел меньше **5 с** назад (перезахват — узел «ходит по рукам»); идёт шаг обучения, открыто меню, тянется свайп или выбирается цель приёма (бой и так на `SLOW_MO`); бой окончен (последний захват → победная волна FX-9).
- **Готово, когда:** тесты на все ветки функции зелёные; быстрый захват трёх нейтралов подряд даёт один стоп-кадр; затяжная борьба за узел не «спотыкается».

## FX-9. Победная волна
- В `endBattle` при победе игрока, до показа панели результата (`RESULT_DELAY_MS` = 700 мс; если волне не хватает — увеличить задержку до ~1100 мс, **спросить пользователя**).
- Из столицы игрока (если её нет — из последнего захваченного узла) по полю расходится круг: заливка светло-синяя с альфой 0.16 → 0, контур 4 px с альфой 0.7 → 0, скорость ~520 px/с в масштабе прототипа (считать от размера поля, чтобы волна проходила всё поле за ~1 с).
- Каждый узел, которого коснулась волна: `pop` + маленький всплеск конфетти (14 частиц из эмиттера FX-7).
- Волна заканчивается до появления панели результата (на экране результата уже есть своя нагрузка, PF-7).
- Звёзды на поле не показывать.
- **Готово, когда:** победа ощущается как финал; экран результата появляется после волны, без просадки FPS.
