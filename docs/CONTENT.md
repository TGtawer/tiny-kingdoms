# План нового контента

Статус: v0.1, после MVP главы 1. Задача — убрать однообразие: сейчас уровни отличаются только числами и раскладкой узлов, а враг всегда ведёт себя одинаково. К 5–6 уровню выигрышная стратегия уже найдена, и дальше игрок её просто повторяет.

Цель документа — чтобы **у каждого уровня была своя «фишка»**: особый узел, характер врага, необычная цель или босс.

Документ — список задач для Claude Code. Делать **по этапам C-1 → C-5**, каждый этап — отдельная ветка/PR. Ощущения от игры (звук, тряска, ускорение ×2) сюда не входят — они уже описаны в `UX.md` (UX-3, UX-4).

## Общие правила (дополняют CLAUDE.md)

- Все правила из `CLAUDE.md` действуют: логика в `src/core/` без Phaser и с тестами; числа — в `src/config/balance.ts`; размеры и цвета рендера — в `src/config/game.ts`; весь текст через i18n (`ru.json` + `en.json`).
- Каждая задача меняет геймдизайн: в том же PR обнови `docs/GDD.md` и `docs/BALANCE.md`.
- Числа ниже — **стартовые**, их подбирают на плейтесте.
- Новые поля уровня — необязательные, со значением по умолчанию: старые уровни главы 1 должны валидироваться и играться без правок. Валидация — в `src/core/level/schema.ts`, тесты — в `tests/core/`.
- ИИ врага учитывает каждую новую механику (хотя бы на простом уровне), иначе её можно обыграть одним приёмом. Smoke-тест «ИИ против ИИ» должен проходить на всех уровнях.
- Каждую новую механику игроку **показывают**, а не объясняют текстом: при первой встрече — одна короткая подсказка с подсветкой узла (механизм `tutorials.json`).
- После этапа: `npm run lint && npm run test && npm run build`, проверка в 360×640 и 1280×720.

## C-1. Особые узлы [GDD]

В схеме узла появляется поле `kind?: 'normal' | 'temple' | 'fortress' | 'chest' | 'portal' | 'bandits'` (по умолчанию `normal`). Особый узел визуально отличается иконкой и формой (рисуется кодом), а при тапе показывает короткую подпись с эффектом.

### 1.1 Храм
- Не производит ни войск, ни базового золота. Постройки на нём нельзя ставить.
- Пока храм у тебя, **весь доход золота владельца +50%** (`temple.goldBonus = 0.5`). Два храма дают +100%.
- На старте обычно нейтральный, с крупным гарнизоном (15–25).
- ИИ: ценит храм как цель выше обычного узла того же гарнизона.
- **Готово, когда:** в бою видна иконка храма, золото в HUD растёт быстрее после захвата, есть тест в `economy`.

### 1.2 Крепость
- При обороне каждый защитник считается за **×2** (`fortress.defenseMult = 2`). Множитель складывается с силой юнитов из прокачки и стоит после урона башни (порядок как в GDD §3.6).
- Производит войска как узел своего размера, постройки разрешены.
- После захвата остаётся крепостью — у нового владельца.
- ИИ: при оценке атаки учитывает множитель; любит держать крепость на границе.
- **Готово, когда:** превью исхода атаки (UX 1.4) учитывает множитель; есть тест в `combat`.

### 1.3 Сундук
- Нейтральный, не производит. При захвате владелец **сразу получает `chest.gold = 60` золота**, затем узел становится обычным малым узлом.
- Эффект: сундук открывается, всплывает «+60».
- Это решение «рискнуть ради быстрого старта или копить силы».
- ИИ: берёт сундук, если тот ближе любой выгодной цели.
- **Готово, когда:** награда выдаётся один раз и только при захвате; есть тест.

### 1.4 Портал
- Порталы идут парами: у двух узлов одинаковое поле `portalPair: string`.
- Между узлами пары — невидимая дорога. Армия входит в портал, исчезает и через `portal.delayMs = 1000` появляется у второго портала.
- Правило «промежуточные точки — только свои узлы» (GDD §3.5) действует: через портал можно идти, только если входной портал свой. Выходной может быть целью атаки.
- Столкновений на дороге-портале нет.
- Pathfinding учитывает портал как ребро с весом, равным пути за `delayMs`.
- ИИ: использует портал так же, как обычную дорогу (через общий pathfinding).
- **Готово, когда:** армия проходит через портал с эффектом исчезновения и появления; есть тест в `pathfinding`.

### 1.5 Лагерь разбойников
- Нейтральный узел, который, в отличие от нейтралов, **производит войска** (как малый узел) до вместимости.
- Каждые `bandits.raidEveryMs = 20000` отправляет 75% войск в ближайший по дорогам узел игрока или врага (при равенстве — в более слабый). Если соседей-не-нейтралов нет, не нападает.
- После захвата становится обычным узлом.
- Логика — в `src/core/sim/` (отдельный модуль `bandits.ts`), не в `EnemyAI`.
- **Готово, когда:** разбойники нападают по таймеру на обе стороны; поведение детерминировано (через `rng.ts`), есть тест.

## C-2. Характеры врагов [GDD]

Параметры ИИ уже есть (`EnemyParams`); здесь их упаковывают в узнаваемых правителей.

- В `EnemyParams` появляется поле `leader?: LeaderId`. Пресеты лидеров — в `balance.ts`: агрессивность, частота решений, приоритеты построек, весовые коэффициенты выбора целей. Поля уровня (`aggression` и т. д.) переопределяют пресет.
- Перед боем — карточка лидера: портрет (рисуется кодом), имя, одна фраза. Закрывается тапом или сама через 2,5 с. Пауза боя, пока карточка открыта.
- Портрет лидера виден в HUD рядом с золотом врага.

| Лидер | Ключ | Поведение | Как обыграть |
|---|---|---|---|
| Король Крепкий | `king` | Оборонец: строит башни на границе, атакует только в ответ или при большом перевесе | Быстро забрать нейтралы и экономику |
| Барон Буйный | `baron` | Агрессор: атакует рано и часто, почти не строит | Отбиться в башне/крепости, контратаковать опустевшие узлы |
| Гном Скряга | `dwarf` | Строитель: сначала шахты и казармы, атакует поздно большой армией | Давить рано, пока не раскачался |
| Ведьма Хитрая | `witch` | Оппортунист: бьёт по узлам игрока, которые только что отправили войска | Не оголять тыл, отправлять тапом (50%) |

- Для ведьмы в `EnemyAI` нужна оценка «узел ослаб за последние N с» — вычисляется в `src/core/`, с тестом.
- **Готово, когда:** у каждого лидера свой тест в `tests/core/ai/` на характерное поведение (например, `dwarf` строит шахту раньше первой атаки).

## C-3. Цели уровней [GDD]

В схеме уровня появляется `goal?: Goal` (по умолчанию `conquer`).

| Цель | Ключ | Победа | Поражение |
|---|---|---|---|
| Завоевание | `conquer` | У врага нет узлов (как сейчас) | У игрока нет узлов |
| Удержание | `hold` | Держать узел `nodeId` `seconds` секунд подряд (таймер сбрасывается при потере) **или** обычное завоевание | У игрока нет узлов |
| Оборона | `survive` | Продержаться `seconds` секунд **или** обычное завоевание | У игрока нет узлов |
| Столица | `capital` | Захватить столицу врага (`capital: true`) | Потерять свою столицу или все узлы |

- Цель `capital` даёт геймплейный смысл столицам, которые сейчас только визуальные (см. `TODO(design)` в `schema.ts`).
- Цели «на время» сознательно не делаем: аудитория 35+, в GDD — «никакой спешки».
- Для `survive` врагу задаётся усиленное производство и высокая агрессивность в параметрах уровня; отдельной системы волн не нужно.
- HUD: под верхним баром — плашка цели с текстом и прогрессом (кольцо таймера над удерживаемым узлом для `hold`).
- Логика — в `src/core/sim/victory.ts`, с тестами на каждую цель.
- **Готово, когда:** каждая цель играется на тестовом уровне; экран результата пишет, какая цель выполнена.

## C-4. Боссы 10-х уровней [GDD]

Закрывает открытый вопрос GDD §7.1. Используется существующее поле `special` в схеме уровня. Логика каждого босса — отдельный модуль в `src/core/sim/specials/`.

### 4.1 Дракон (глава 1, уровень 10)
- Каждые `dragon.everyMs = 20000` дракон сжигает **50%** войск в узле с самым большим гарнизоном на поле (игрока или врага, нейтралы не трогает). При равенстве выбор через `rng.ts`.
- **За 3 с до удара** над целевым узлом появляется тень и красный круг: игрок успевает увести войска или, наоборот, подставить врага.
- Победа — обычное завоевание.
- Суть: наказывает за накопление армии в одном узле.
- ИИ: при предупреждении над своим узлом отправляет из него войска (если есть куда).

### 4.2 Цитадель (глава 2, уровень 10)
- У врага один большой узел-крепость (`fortress`) с гарнизоном 150 и казармами 3-го уровня.
- Каждые `citadel.waveEveryMs = 15000` цитадель выпускает отряд из 20 юнитов (сверх гарнизона) в ближайший узел игрока.
- Цель — `capital` (столица = цитадель).
- Суть: сначала надо выстроить оборону и экономику, потом штурмовать.

- **Готово, когда:** дракон и цитадель играются, ИИ-против-ИИ на этих уровнях заканчивает бой.

## C-5. Второй враг: три стороны [GDD]

Самая дорогая задача: меняет модель владельцев. Делать последней, когда C-1…C-4 проверены.

- `LevelOwner` расширяется до `'player' | 'enemy' | 'enemy2' | 'neutral'`. Цвет второго врага — зелёный (контрастен синему, красному и серому).
- В схеме уровня — необязательное поле `enemy2?: EnemyParams`. Если узлов `enemy2` нет, поведение как сейчас.
- Каждый враг управляется своим экземпляром `EnemyAI`. **Враги воюют друг с другом**: игрок и второй враг для ИИ равноценные цели (с поправкой на характер лидера).
- Столкновения на дорогах — между любыми разными сторонами.
- Победа: не осталось узлов ни у одного врага. Если один враг выбыл, бой продолжается против второго.
- Аудит всех мест, где сейчас сравнение `owner === 'enemy'`: ИИ, `victory.ts`, рендер, HUD, превью, разбойники, дракон.
- **Готово, когда:** на тестовом уровне видно, как два ИИ дерутся между собой; все тесты и smoke проходят.
