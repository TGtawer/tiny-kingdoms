Статус: v0.1, переработка обучения главы 1. Закрывает открытый вопрос GDD §7.3 («детальный сценарий обучения»).

Документ — список задач для Claude Code. Делать **строго по этапам T-1 → T-7**, каждый этап — отдельная ветка/PR. Следующий этап начинать только после того, как предыдущий прошёл проверку. Внутри этапа задачи идут в указанном порядке.

## Идея в двух словах

- Игрок учится **делом, а не чтением**: на каждом шаге обучения — подсветка, палец и 3–6 слов текста. Пока игра ждёт действия, бой идёт **сильно замедленно** (15% скорости; так же — при выборе постройки и во время свайпа, GDD §3.5).
- Механики открываются по одной: **чему ещё не научили — того нет** (или оно затемнено и с замком). Золото не показывается, пока его не на что тратить.
- Ритм главы 1: **урок → закрепление**. После уровня 6 игрока за руку ведут в «Прокачку» и выдают первый приём.
- Спецприёмы не выбираются, а **выдаются по сюжету**: подкрепление — после уровня 6, огненный шар — за победу над злым магом (глава 1, ур. 10), щит — за босса главы 2.

## Общие правила (дополняют CLAUDE.md)

- Все правила `CLAUDE.md` действуют: логика — в `src/core/` без Phaser и с тестами; числа — в `src/config/balance.ts`; размеры и цвета рендера — в `src/config/game.ts`; весь текст — через i18n (`ru.json` + `en.json`, ключи добавлять в оба).
- Каждый этап меняет геймдизайн там, где GDD ещё описывает старое: **в том же PR сверь** `docs/GDD.md` и `docs/BALANCE.md` с этим документом. Документы уже обновлены под решения ниже; если найдёшь расхождение — правь документ под этот файл и напиши об этом в PR.
- Числа — стартовые, их подбирают на плейтесте.
- Ничего не удаляем «насовсем», если это не сказано явно: дракон, шахты, карточки лидеров остаются в коде, просто не используются в главе 1.
- После этапа: `npm run lint && npm run test && npm run build`, проверка в портрете 360×640 и альбоме 1280×720.

## T-1. Один жест: убрать тап-тап [GDD §3.5]

Отправка войск — **только свайп** (от одного узла или через несколько своих узлов), всегда **75%**. Тап по своему узлу **всегда** открывает меню построек.

1. Ввод (`BattleScene`): убрать режим «выбран узел → тап по цели». Тап по своему узлу → меню построек; тап по чужому/нейтральному узлу → ничего (тап по особому узлу по-прежнему показывает его подпись, GDD §3.12).
2. Превью: убрать бейдж «→ N» над выбранным узлом (UX 1.3, вторая половина). Бейдж у конца линии свайпа остаётся.
3. `core`: режим отправки `'tap'` больше не доступен игроку. ИИ продолжает **внутри** подтягивать войска из тыла на 50% — это его внутреннее правило, игрок его не видит. Переименуй режим в `'pull'`, чтобы не путать с жестом, и оставь его только для ИИ.
4. Обучение: убрать `finger.kind: 'tapTap'` из `TutorialView`/схемы, ключ `tut.tapTap` из i18n, шаг с тап-тапом из `tutorials.json`.
5. Тесты: «свайп 75%» остаётся; тест на 50% переписать под режим ИИ `'pull'`.

- **Готово, когда:** с мыши и пальцем можно отправить войска только свайпом; тап по своему узлу всегда открывает меню; ИИ играет как раньше (smoke «ИИ против ИИ» проходит).

## T-3. Открытие механик [GDD §3.8, §6]

### 3.1 Таблица открытий
- Новый модуль `src/core/meta/unlocks.ts` (чистая функция, тесты):
  ```ts
  type Feature = 'barracks' | 'tower' | 'mine' | 'upgrades';
  // available in battle on `levelId` with save `progress`
  function isFeatureAvailable(f: Feature, levelId: string, progress: Progress): boolean;
  function isGoldVisible(levelId: string, progress: Progress): boolean; // any building or spell available
  ```
- Таблица — в `balance.ts`, `FEATURE_UNLOCKS`: `barracks: 'c01_l03'`, `tower: 'c01_l05'`, `mine: 'c02_l01'`, `upgrades: { afterWin: 'c01_l06' }`.
- Правило для построек: постройка доступна, если порядковый номер её уровня ≤ max(номер текущего уровня, номер следующего непройденного). Так при переигрывании уровня 1 после уровня 5 казармы и башня уже есть, а при первом прохождении — нет.
- Враг играет по своим правилам и все постройки ему доступны (но жил в главе 1 нет, поэтому шахт у него тоже нет).

### 3.2 Замки в интерфейсе
- **Меню построек:** недоступная постройка показывается **на тёмном фоне со значком замка** вместо цены. Тап по ней → короткая всплывающая подпись «Откроется на уровне N» (`lock.atLevel`, параметр `index`), постройка не строится. Шахта, как и раньше, показывается только на узле с жилой.
- **Кнопка «Прокачка»** в главном меню и на карте глав: до победы на уровне 6 — тёмная, со значком замка; тап → подпись «Откроется после уровня 6» (`lock.afterLevel`). Знамя меню (V-4) — тот же приём: затемнение + замок на медальоне.
- **Счётчик золота** в HUD скрыт, пока `isGoldVisible` ложно (уровни 1–2 при первом прохождении). Золото в симуляции при этом копится как обычно — скрыт только вывод.
- **Кнопка приёма** в HUD скрыта, пока у игрока нет ни одного открытого приёма.

### 3.3 Приёмы по сюжету (вместо слотов за звёзды)
- `spellbook.ts`: убрать слоты за звёзды (`SPELL_SLOT_STARS`) и выбор приёма в слот. Вместо этого в сохранении — список `unlockedSpells` и `activeSpell`.
- Порядок выдачи — в `balance.ts`, `SPELL_UNLOCKS`: `reinforce` — шаг тура «Прокачки» (T-6); `fireball` — победа на `c01_l10`; `shield` — победа на `c02_l10` (TBD, главы 2 пока нет).
- Первый открытый приём сразу становится активным. Новый приём активным **не** становится сам: на экране победы — «Новый приём: …» и подсказка «Сменить приём можно в Прокачке» (`result.newSpell`, `result.switchSpellHint`).
- В бой по-прежнему берётся один активный приём.
- **Звёзды** теперь тратятся только на улучшения приёмов (цены те же, BALANCE.md). Улучшать можно только открытые приёмы.
- Экран победы больше не пишет «появился свободный слот».
- Советы на экране поражения (`tips.ts`) предлагают только открытое: совет про казармы — если казармы доступны; про шахту — если шахта доступна; кнопка «Прокачка» — если прокачка открыта.

### 3.4 Сохранение
- Версия сохранения +1, миграция: старые выборы слотов отбросить; потраченные на улучшения приёмов звёзды вернуть; `unlockedSpells` = `[reinforce]`, если пройден `c01_l06` (тур считать пройденным), плюс `fireball`, если пройден `c01_l10`. Сохранения были только у разработчика, сложного переноса не нужно.

- **Готово, когда:** на чистом сохранении на уровнях 1–2 нет золота и кнопки приёма, в меню построек казармы и башня под замком; на уровне 3 появились золото и казармы, на 5 — башня; «Прокачка» под замком до победы на 6; тесты на `unlocks`, `spellbook`, `tips`, миграцию.

## T-4. Движок обучения [GDD §6]

Механизм шагов (`src/core/tutorial/tutorial.ts`, `tutorials.json`, `TutorialView`) остаётся; расширяем.

1. **Замедление.** Новое поле шага `slow: true`. Пока текущий шаг с `slow`, вся симуляция (производство, армии, ИИ, таймеры, перезарядки) идёт со скоростью `SLOW_MO.speed = 0.15` (т. е. на 85% медленнее; после плейтеста было 0.2). Анимации интерфейса — палец, подсветка, меню — идут с обычной скоростью. Как только шаг выполнен — скорость сразу ×1. Множитель — в `balance.ts`. Реализация: `battleSpeed` в `src/core/sim/clock.ts` — то же замедление действует, пока открыто меню построек или идёт свайп; кнопки ускорения во время шага с `slow` нет.
   - `slow` ставится **только** на шаги, где игра ждёт действия игрока. Валидатор: шаг с `until.type === 'time'` не может быть `slow`.
2. **Новые условия шагов** (`StepCondition`):
   - `{ type: 'send', to?, minSources? }` — `minSources: 2`: один свайп прошёл через ≥ 2 своих узла;
   - `{ type: 'spellSelect' }` (UI) — игрок нажал кнопку приёма;
   - `{ type: 'cast', spell? }` — приём применён;
   - `{ type: 'special', event: 'mageWarning' | 'mageStrike' }` — событие босса (для T-7);
   - `{ type: 'any', of: StepCondition[] }` — выполнено любое из условий.
3. **Шаг без текста.** `hint` становится необязательным: такой шаг ничего не показывает и просто ждёт условия (нужен, чтобы показать подсказку в нужный момент, например, когда армия дошла).
4. **Информационные шаги** (`until: time`) — не больше одного на уровень, до 4 с, без замедления. Длинных объяснений нет.
5. **Только первое прохождение.** Сценарий запускается, только если уровня нет в `progress.completed`. При переигрывании — без подсказок и без замедления.
6. Удалить `finger.kind: 'tapTap'` (если не сделано в T-1). Палец поддерживает: `drag` (в т. ч. через несколько узлов — `path: string[]`), `tap` (узел), `tapUi` (элемент HUD: `gold`, `spell`).
7. Обновить `validateTutorial` под новые поля; тесты на замедление (шаг `slow` → тиков на кадр меньше), `any`, `minSources`, шаг без текста, запуск только при первом прохождении.

- **Готово, когда:** тесты на новые условия зелёные; на тестовом сценарии видно, что бой почти стоит, пока игрок не выполнил шаг, и сразу ускоряется после.

## T-6. Тур «Прокачки» после уровня 6 [GDD §4.3, §6]

После первой победы на уровне 6 игрока ведут: экран победы → карта глав → «Прокачка» → открыть «Подкрепление» → обратно на карту.

1. **Состояние тура** — в сохранении: `onboarding.upgradesTour: 'pending' | <номер шага> | 'done'`. Логика шагов — чистая функция в `src/core/meta/onboarding.ts` (без Phaser), тесты. Сохранять после каждого шага.
2. **Экран победы уровня 6** (первая победа): кнопка «Далее» ведёт на карту, а не в следующий уровень. Межуровневая реклама — как обычно, до перехода.
3. **Шаги тура:**
   1. Карта глав: затемнение всего, кроме кнопки «Прокачка»; палец на ней; текст «Тебя ждёт новый приём!» / «A new spell awaits!». Остальные кнопки и уровни не нажимаются.
   2. «Прокачка», блок кристаллов: подсветка; «Кристаллы — за победы. Тратятся на бонусы навсегда» / «Crystals come from wins. Spend them on permanent bonuses». Дальше — тап в любом месте.
   3. Блок приёмов и звёзд: подсветка; «Звёзды — за лучшие победы. Тратятся на улучшение приёмов» / «Stars come from great wins. Spend them on spell upgrades». Дальше — тап.
   4. Карточка «Подкрепление»: палец; «Открой «Подкрепление»» / «Unlock Reinforcement»; до этого кнопка «Назад» не работает. Тап → приём открыт и активен, эффект открытия.
   5. «Готово! Возвращайся в бой» / «Done! Back to battle» — палец на «Назад» → карта, текущий уровень 7. Тур `done`.
4. **Продолжение после перезапуска:** если при загрузке тур не `done` и уровень 6 пройден — `BootScene` открывает сразу карту (не меню) и продолжает тур с сохранённого шага (шаги 2–4 — сразу «Прокачку»).
5. Подсветка и затемнение — общий компонент для сцен вне боя (`view/Spotlight.ts`): прямоугольник/круг-«дырка» в тёмном оверлее, палец, одна строка текста. Зона касания ≥ 48 px.

- **Готово, когда:** с чистого сохранения после победы на 6 тур проходит до конца; если закрыть игру на любом шаге и открыть снова — тур продолжается; после тура на уровне 7 есть кнопка приёма; тесты на `onboarding`.

## T-7. Босс «Злой маг» (глава 1, уровень 10) [GDD §4.1]

Злой маг сидит в своей башне — столице врага — и кидает огненные шары по узлам игрока. Победа — захват башни мага. Награда — приём «Огненный шар».

1. **Механика** — модуль `src/core/sim/specials/mage.ts`, `special: { type: 'mage' }`, числа — `MAGE` в `balance.ts`:
   - каждые `MAGE.everyMs = 20000` выбирается узел **игрока** с самым большим гарнизоном (при равенстве — через `rng.ts`);
   - за `MAGE.warnMs = 3000` до удара над ним — красный круг предупреждения (как у дракона) и событие `mageWarning`;
   - удар (`mageStrike`): огненный шар летит из башни в цель и уничтожает `MAGE.damageShare = 0.4` гарнизона (минимум `MAGE.damageMin = 5`) — те же числа, что у приёма 1-го уровня;
   - маг кидает, пока башня у врага. Узлы врага и нейтралов не трогает;
   - логику дракона переиспользовать (общий таймер «предупреждение → удар»), но дракона не ломать — его тесты должны проходить.
2. **Уровень:** цель `goal: { type: 'capital' }`; столица врага = башня мага (большой узел, отрисованный как башня мага — фиолетовая, кодом). ИИ — обычный, средней агрессивности, без лидера. Музыка — `music_boss` (AUDIO.md).
3. **Сценарий** (`c01_l10`):
   1. «Злой маг! Захвати его башню» / «An evil mage! Take his tower» — подсветка башни; `until: time 4`.
   2. (без текста) — `until: special mageWarning`.
   3. «Огненный шар! Уводи войска» / «Fireball! Move your troops out» — подсветка цели удара; `until: any [send, special mageStrike]`; `slow`.
4. **Награда:** первая победа на `c01_l10` открывает `fireball` (T-3 §3.3); экран победы показывает «Новый приём: Огненный шар!» и подсказку про смену в «Прокачке».
5. **ИИ игрока в тестах** (`tests/levels.test.ts`) уводит войска из отмеченного узла, как при драконе. Подобрать сложность: 5–7/10.
6. Тесты: интервал, выбор цели, предупреждение раньше удара, урон с минимумом, остановка после захвата башни, выдача награды один раз.

- **Готово, когда:** уровень 10 играется против мага, предупреждение видно за 3 с, после победы открыт огненный шар; дракон работает на dev-уровне.
