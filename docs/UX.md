# План улучшений UX

Статус: v0.1, после MVP главы 1. Источник — ручной плейтест в портрете 360×640 и альбоме 1280×720 и разбор кода `BattleScene`, `BattleHUD`, `NodeView`, `BuildMenu`, `MenuScene`, `ChapterMapScene`.

Документ — список задач для Claude Code. Делать **по этапам UX-1 → UX-4**, каждый этап — отдельная ветка/PR. Внутри этапа задачи независимы.

## Общие правила (дополняют CLAUDE.md)

- Все правила из `CLAUDE.md` действуют: логика в `src/core/` без Phaser и с тестами; числа баланса — в `src/config/balance.ts`; размеры и цвета рендера — в `src/config/game.ts`; весь текст — через i18n (`ru.json` + `en.json`, тест `tests/i18n.test.ts` должен проходить).
- Каждую задачу проверять в портрете 360×640 и альбоме 1280×720. Зона касания ≥ 48 px.
- Задачи с пометкой **[GDD]** меняют геймдизайн: в том же PR обнови `docs/GDD.md` (и `BALANCE.md`, если появились числа). Если задача требует решения, которого здесь нет, — `// TODO(design): ...`, не выдумывай.
- Новая логика, которую можно вынести из рендера (превью исхода атаки, расчёт звёзд, доход в секунду), — в `src/core/` с тестами в `tests/core/`.
- После этапа: `npm run lint && npm run test && npm run build`.

## UX-1. Первые 30 секунд и прозрачность правил

Самый большой эффект: на Яндекс Играх основной отток — до первого осмысленного действия.

### 1.1 Первый запуск — сразу в бой
- Если `progress.completed` пуст (первый запуск), `BootScene` стартует `BattleScene` с первым уровнем, минуя `MenuScene` и `ChapterMapScene`.
- Выход из боя (пауза → «К карте», экран результата) ведёт на карту как обычно.
- **Готово, когда:** с чистым сохранением после загрузки сразу открывается уровень 1 с обучением; со вторым запуском — меню.

### 1.2 «Играть» запускает следующий уровень
- В `MenuScene` кнопка «Играть» стартует `BattleScene` с `currentLevel(progress, ALL_LEVELS)` (`src/core/meta/Progress.ts`).
- Добавить вторую кнопку «Карта» (новый ключ i18n `menu.map`) → `ChapterMapScene`. «Прокачка» остаётся.
- На кнопке «Играть» подпись с номером уровня, например «Играть · Ур. 4» (ключ `menu.playLevel` с параметром `index`).

### 1.3 Превью отправки: сколько уйдёт
- Во время свайпа (`drag.moved`) у конца линии рисовать бейдж с суммой войск, которые уйдут: Σ `sendAmount(node.troops, 'swipe')` по всем `drag.sources`, у которых есть путь к цели.
- При выбранном узле (тап-тап) показывать над ним бейдж «→ N» с `sendAmount(troops, 'tap')`.
- Бейдж обновляется каждый кадр, без пересоздания объектов (переиспользовать `Text`).
- **Готово, когда:** игрок видит число до отпускания пальца; число совпадает с размером ушедшей армии.

### 1.4 Превью исхода атаки
- В `src/core/sim/` добавить чистую функцию `previewAttack(world, side, sources, mode, targetId)` → `{ sent: number; defenders: number; wins: boolean }`. Учитывать гарнизон цели на момент отправки, урон башни (`towerDamage`) и силу юнитов (модификаторы сторон) — те же формулы, что в `combat.ts`/`capture.ts`. Производство цели за время пути не учитывать (это превью, не гарантия). Покрыть тестами.
- Цвет линии свайпа: зелёный — `wins`, жёлтый — не хватает, красный — нет пути (как сейчас). Цвета добавить в `COLORS`.
- Для своей цели (подкрепление) — обычный белый.

### 1.5 Понятный отказ «нет пути»
- В `handleEvent` → `rejected` с `noPath`: кроме красного кольца, `floatText` с i18n-ключом `battle.noPath` («Нет пути» / «No route»).
- Подсветить красным кольцом чужой узел, который перекрывает кратчайший путь по дорогам (если такой есть). Поиск этого узла — чистая функция в `pathfinding.ts` с тестом.

### 1.6 Замки видны
- Стартовые узлы игрока и врага (как они помечены в схеме уровня) рисовать с иконкой замка/короны в `NodeView` (рисовать кодом в `icons.ts`). Иконка остаётся у узла после смены владельца — это «столица».
- Если в схеме уровня нет признака стартового узла — добавить необязательное поле, обновить `schema.ts`, валидацию и уровни главы 1. **[GDD]** — уточнить, есть ли у столицы игровой смысл; пока только визуальный.

## UX-2. Читаемость поля и экономики

Целевая аудитория 35+ (GDD §1): крупно и без мелкого текста.

### 2.1 Крупнее узлы в портрете
- Сейчас у малых узлов в 360×640 радиус упирается в `NODE_RADIUS_MIN_PX = 20`, а по бокам поля много пустой травы.
- Поднять `NODE_RADIUS_MIN_PX` до ~26 и пересмотреть `NODE_RADIUS` так, чтобы на уровнях главы 1 узлы занимали больше доступной ширины. Узлы не должны перекрываться и налезать на дороги — проверить на всех 10 уровнях в обеих ориентациях.
- **Готово, когда:** число войск в самом маленьком узле читается без усилия на 360×640; скриншоты всех уровней главы 1 в портрете без перекрытий.

### 2.2 Убрать мелкую подпись вместимости
- Подпись «/50» (`capText`, ~11 px) не читается. Убрать её с поля; вместимость показывать только у выбранного узла (в меню построек или рядом с ним). Дуга заполнения остаётся.
- Число войск после этого центрировать в круге.

### 2.3 Доход золота в HUD
- Рядом со счётчиком золота — «+N/с» мелким шрифтом: сумма `goldRate` по узлам игрока (`economy.ts`). Вынести сумму в чистую функцию `sideGoldRate(world, side)` с тестом.
- При росте дохода (захват, шахта) — короткая вспышка подписи.

### 2.4 Меню построек объясняет эффект
- Под названием постройки одна строка эффекта: ключи `building.<type>.desc` («Больше войск и быстрее», «+много золота», «Бьёт входящих врагов»). Для улучшения — что даст следующий уровень.
- Если золота не хватает — вместо серой кнопки показывать «ещё N» с монетой (N = цена − золото), обновлять в `refresh()`.

## UX-3. Ощущения (juice) и звук

### 3.1 Звук
- Минимальный набор: отправка армии, захват узла (свой/потерян — разные), постройка, файрбол, победа, поражение, клик по кнопке.
- Генерировать кодом через Web Audio (короткие синтезированные звуки) или маленькие ассеты — по правилу 8 из CLAUDE.md предпочтительно кодом.
- Модуль `src/view/sound.ts` с одной точкой входа `playSfx(id)`. Пауза звука при паузе игры, скрытии вкладки и рекламе (требование Яндекса).
- Настройка «Звук вкл/выкл» в паузе; хранить в сохранении (см. `TODO(stage-7)` в `SaveData.ts`, с миграцией версии).

### 3.2 Вибрация
- `navigator.vibrate` (через обёртку в `src/platform/`, т.к. это API окружения): короткий импульс при захвате узла игроком и при потере своего, длинный — победа. Отключается вместе со звуком. На iOS вызов не поддерживается — просто ничего не делать.

### 3.3 Живые армии
- `ArmyView`: лёгкое покачивание или пульсация при движении и след (2–3 затухающие точки позади). Без отдельных юнитов — правило 7 CLAUDE.md. Проверить FPS на уровне с максимумом армий.

### 3.4 Удар камеры
- Небольшая тряска камеры (`cameras.main.shake`, ~150 мс, слабая) при захвате вражеской столицы и при взрыве файрбола.

### 3.5 Экран победы
- Кристаллы награды анимированно «летят» к счётчику и тот досчитывает до нового значения.
- Кнопка «Дальше» крупнее остальных и визуально главная.

## UX-4. Темп и удержание

### 4.1 Ускорение ×2 [GDD]
- **Частично сделано в UX-1:** кнопка ×1/×2 есть, но появляется только при контроле больше 65% узлов (GDD §3.11). Здесь осталось решить, нужна ли она с самого начала боя.
- Кнопка в верхнем баре боя (рядом с паузой), переключает ×1/×2. Реализация — число тиков за кадр в `BattleScene.update`, симуляция не меняется (детерминизм сохраняется).
- Не сохранять между боями (по умолчанию ×1).

### 4.2 Звёзды за уровень [GDD]
- 3 звезды: победа; победа быстрее порога времени; победа без потери ни одного своего узла. Порог времени — поле уровня в JSON (с разумным значением по умолчанию в `balance.ts`).
- Расчёт — чистая функция в `src/core/meta/` с тестами. Хранить лучший результат в `Progress` (новое поле + миграция сохранения).
- Показывать на экране победы (по одной, с анимацией) и под узлами на карте глав.
- Влияют ли звёзды на награду — **TBD**, пока нет.

### 4.3 Подсказка при поражении
- На экране поражения — один совет. Выбирать по простым правилам из итога боя: не строил казармы → совет про казармы; есть шахтный узел без шахты → совет про шахту; есть непотраченные кристаллы на прокачку → кнопка «Прокачка». Правила — чистая функция с тестами, тексты — `tip.*` в i18n.

### 4.4 Карта глав
- При входе карта прокручивается к текущему уровню (`currentLevel`), он пульсирует.
- Пройденные уровни — со звёздами (после 4.2).
