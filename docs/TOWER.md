# TOWER — башня бьёт по дорогам (этапы TW-1…TW-5)

Переделка башни: вместо выстрела по юниту, который уже дошёл до узла, башня держит под огнём **начало каждой дороги** своего узла на фиксированную длину и стреляет по врагам, идущим к узлу по этим участкам. Участок виден на дороге.

## Правила работы
- Каждый этап — **отдельный коммит** (сообщение на английском), коммит и пуш — только после подтверждения пользователя.
- После каждого этапа: `npm run lint && npm run test && npm run build`; для TW-1 ещё `npm run bench`.
- Документы дизайна (GDD, BALANCE, ARCHITECTURE, TUTORIAL) правятся ровно так, как записано в TW-5; всё сверх этого — сначала согласовать.
- Если по ходу появляется вопрос геймдизайна, которого нет здесь, — спросить, не решать самому.

## Решения (согласовано 2026-11-08)
1. **Зона башни** — участок каждой дороги узла длиной `BUILDINGS.tower.zone = 0.13` ширины поля, считая **от центра узла**. Длина фиксированная и не зависит от длины ребра.
   - Откуда число: среднее ребро главы 1 (97 рёбер) было 0.295 между центрами. После PLAYTEST-2 — 0.323, медиана 0.305, разброс 0.30–0.47; зона 0.13 — 40% среднего ребра.
   - Все дороги не короче 0.30 (`LEVEL_LIMITS.minRoadLength`), зоны башен на двух концах не пересекаются, между ними ≥ 0.04.
2. **Уровень башни** меняет только темп: 1 / 2 / 3 выстрела в секунду (как сейчас). Длина зоны одна для всех уровней.
3. **По кому стреляет:** только по юнитам, которые идут **к узлу башни** по его дорогам (полоса дороги с `to` = узел башни) и находятся в зоне: расстояние до центра узла ≤ `zone`. Свои юниты и юниты на других дорогах не трогает. «Враг» — как сейчас: любая сторона, кроме владельца узла (башня нейтрального узла бьёт всех, кроме нейтралов).
4. **Цель** — ближайший к узлу враг в зоне (голова колонны).
5. **Темп** — прежние правила: перезарядка `1 / темп` с, один выстрел держится наготове, поэтому первый вошедший в зону враг гибнет сразу. Не больше одного выстрела башни за тик.
6. **У самого узла башня больше не стреляет.** Юнит, прошедший зону, приходит в узел и бьётся с гарнизоном 1:1 (или захватывает), как в узле без башни.
7. **Выстрел — не нападение.** Юнит, сбитый башней на дороге, не ставит узлу `attackedUntilMs`: производство и потоки узла не прерываются. Нападение — только когда враг дошёл до узла (GDD §3.6, «Нападение на узел»).
8. **Порталы:** невидимая дорога портала не покрывается (на ней юнит не виден).
9. **Захват:** башня переходит новому владельцу (F-3) вместе с перезарядкой и сразу стреляет по врагам нового владельца в своей зоне.
10. **Визуал** (выбран по прототипу `docs/prototypes/tower-zones.html`, вариант «А · Полоса», эффект «Стрела»):
    - **Зона** — полупрозрачная полоса цвета владельца поверх дороги, **ровно в ширину дороги** (вместе с коричневой каймой, не шире и не уже), и поперечная засечка на границе зоны той же длины — ровно поперёк дороги.
    - **Подсветки зоны при выстреле нет.**
    - **Выстрел** — стрела летит от значка башни к юниту, на месте гибели — огненная вспышка.
    - Прототип — эталон вида: открыть в браузере, переключатели «Уровень», «Выстрел: Стрела», «Длина 0.130». Точные числа — ниже в TW-3 и TW-4.

## TW-1. Логика и тесты (`src/core/`)
- `balance.ts`: `BUILDINGS.tower.zone = 0.13` (ширины поля), комментарий про среднее ребро.
- `World`: при загрузке уровня для каждого узла — список индексов **входящих** полос (без порталов), один раз; в тике ничего не строится.
- Новый шаг тика **«выстрелы башен»** — после касаний (`clash.ts`), **до** движения: для каждой башни с готовым выстрелом пройти её входящие полосы; в полосе юниты лежат от головы к хвосту, поэтому берётся первый враждебный юнит с головы; если он в зоне (`(1 − progress) · length ≤ zone`) — кандидат; из кандидатов всех полос — ближайший к узлу. Он погибает (`dropUnit` + чистка полосы), башня перезаряжается по прежней формуле `towerShoots`.
- `combat.ts`: из `arriveUnit` убрать выстрел башни и исход `destroyedByTower`; `towerRate` остаётся.
- Событие тика `towerShot` (узел башни, сторона и id сбитого юнита, полоса и `progress` в момент выстрела) — для рендера и звука.
- Порядок тика, детерминированность и «никаких аллокаций в горячем цикле» — как в ARCHITECTURE.
- Тесты (Vitest): юнит в зоне сбит, за её границей — нет; ближайший к узлу сбит первым; выстрел наготове + темп 1/2/3 за секунду; свои юниты и юниты на дорогах не к узлу башни не сбиваются; на портальной связи не стреляет; сбитый юнит не ставит `attackedUntilMs`; дошедший до узла — обычный 1:1 без выстрела; после захвата узла башня бьёт по бывшему хозяину; на коротком ребре зона длиннее половины ребра.
- `npm run bench`: бюджет ≤ 0.5 мс на тик сохраняется.
- **Готово, когда:** тесты проходят, `bench` в бюджете, в `dev_stress` и на уровне 5 главы 1 башня сбивает юнитов на дороге.

## TW-3. Зона на дороге (`src/view/`)
- Вид — вариант «А · Полоса» из прототипа:
  - Для каждой дороги узла с башней (кроме порталов): отрезок по оси дороги от точки под кругом узла (начало спрятано под кругом) до `zone` от центра узла. Если дорога короче — не дальше края круга соседнего узла.
  - **Полоса:** линия толщиной **ровно во всю ширину дороги** — как кайма в `RoadView`: `ширина дороги + px(5)`, где ширина дороги `max(px(8), layout.scale · 0.016)`. Цвет `COLORS.faction[владелец]`, прозрачность 0.5. Концы без скругления.
  - **Засечка** на границе зоны: отрезок поперёк дороги длиной ровно во всю ширину дороги (та же `ширина + px(5)`), толщина `px(3.5)`, цвет `COLORS.factionDark[владелец]`, концы скруглены.
  - Слой — над дорогами, под юнитами и узлами. Подсветки при выстреле нет.
- Цвет — **показанного** владельца узла (`DisplayFilter`, F-2), чтобы зона не мигала при частой смене хозяина.
- Зона меняется только при постройке башни, захвате узла с башней и смене раскладки, поэтому каждый кадр не перерисовывается: запекается вместе с лугом и дорогами в текстуру земли (PERF PF-G) и перепекается только при этих событиях.
- Константы отрисовки — в `game.ts` (`TOWER_ZONE`: прозрачность, толщина засечки), длина зоны — из `balance.ts`.
- Проверка в портрете 360×640 и альбоме 1280×720.
- **Готово, когда:** зона видна на всех дорогах узла с башней в обоих ориентациях, меняет цвет при захвате, `npm run profile` не хуже, чем до этапа.

## TW-4. Эффект выстрела
- Вместо вспышки у края узла (сейчас `destroyedByTower` в `BattleScene`) — **стрела** из прототипа:
  - Летит от значка башни на узле к месту гибели юнита за **140 мс** по невысокой дуге (подъём в середине пути `px(10)`, синус).
  - Сама стрела — короткий отрезок длиной около четверти пути, хвостом назад: тёмная обводка `COLORS.outline` толщиной `px(3.2)`, внутри светлая сердцевина `#ffd28a` толщиной `px(1.6)` (новая константа в `game.ts`).
  - Когда стрела долетела — огненная вспышка в точке гибели: `COLORS.fireball`, радиус `px(4)` → `px(11)` за 280 мс с затуханием, светлое ядро в половину радиуса.
  - Симуляция убирает юнита сразу при выстреле. Чтобы фигурка не исчезала раньше, чем долетит стрела, рендер 140 мс показывает «призрак» — ту же фигурку из пула, которая идёт дальше по дороге со скоростью юнитов (не дальше точки прихода в узел), и убирает её вместе со вспышкой. Только отображение, на правила не влияет.
- Стрелы, призраки и вспышки — из пулов, без создания объектов в бою (как вспышки `UNITS_FX`). Отдельного звука у башни сейчас нет (выстрел у узла звучал как удар); звук выстрела — по согласованию, через реестр `AUDIO.md`.
- **Готово, когда:** при 3 выстрелах в секунду у двух башен нет аллокаций в кадре, эффект читается на телефоне.
