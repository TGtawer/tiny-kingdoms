# План разработки

Каждый этап заканчивается проверкой: `npm run lint && npm run test && npm run build`, ручная проверка в браузере в портрете 360×640 и в альбоме 1280×720.

## Этап 0. Каркас
- Vite + TypeScript + Phaser 4, ESLint, Vitest, скрипт `zip`.
- Структура папок из `ARCHITECTURE.md`, `Platform` + `MockPlatform`, i18n с ru/en.
- **Готово, когда:** пустая сцена запускается, тесты и сборка проходят.

## Этап 1. Ядро симуляции (без рендера)
- `World`, тик, производство, золото, отправка армий, pathfinding, бой, захват, постройки, спецприёмы, победа/поражение.
- **Готово, когда:** все правила из GDD §3 покрыты тестами.

## Этап 2. Бой на экране
- `BattleScene`: узлы, дороги, армии с числом, ввод (свайп, мультивыбор; тап-тап убран в этапе 8), меню построек, HUD с золотом и приёмами, пауза.
- Адаптивная раскладка под портрет/альбом.
- Графика рисуется кодом в едином стиле: яркое мультяшное фэнтези, цвета фракций.
- **Готово, когда:** тестовый уровень играется мышью и пальцем до победы.

## Этап 3. ИИ врага
- `EnemyAI` по тем же командам, параметры сложности из уровня.
- Smoke-тест «ИИ против ИИ» по всем уровням.
- **Готово, когда:** ИИ строит, атакует, защищается; бои заканчиваются.

## Этап 4. Уровни и глава 1
- Схема + валидация уровней, генератор черновиков по seed.
- 10 уровней главы 1, включая обучение на уровнях 1–5 (уровень 10 — пока обычный, спецмеханика TBD).
- **Готово, когда:** глава 1 проходится от начала до конца.

## Этап 5. Метапрогрессия
- Карта глав, награды, кристаллы, экран прокачки, открытие приёмов по главам, сохранения (облако + localStorage, версия + миграции).

## Этап 6. Платформа и монетизация
- `YandexPlatform`: init, ready, gameplay start/stop, межуровневая реклама с 3-го уровня, наградная «удвоить», покупки и восстановление покупок, язык.
- Магазин: отключение рекламы, паки кристаллов, стартовый набор.
- **Готово, когда:** игра работает в режиме отладки Консоли Яндекс Игр.

## Этап 7. Полировка и релиз MVP
- Эффекты, звук, экраны победы/поражения, настройки.
- Глава 2 (шахта; щит за босса главы).
- Проверка требований модерации, промоматериалы, публикация.

## Этап 8. Переработка обучения
- По `TUTORIAL.md`, этапы T-1 → T-7 по порядку: один жест (свайп), чистка главы 1, открытие механик с замками, движок обучения с замедлением, уровни 1–9, тур «Прокачки» после ур. 6, злой маг на ур. 10.
- **Готово, когда:** с чистого сохранения глава 1 проходится от начала до конца по новому сценарию, после ур. 6 открыт «Подкрепление», после ур. 10 — «Огненный шар».

## Этап 9. Армии-потоки
Базовая механика по GDD §3.6: войска выходят из узла цепочкой по одному, бой и столкновения — поштучно 1:1. Остальные механики (приёмы, боссы, особые узлы, щит) **заморожены**: в этом этапе их только приводим в рабочее состояние с потоком, правила не меняем. Делать строго по шагам, после каждого — `lint && test && build`.

**P-1. Ядро.** `StreamState`/`UnitState`, полосы дорог, выпуск с темпом, отмена при повторном свайпе и при атаке, запрет свайпа из атакованного узла, окно атаки и пауза производства, приход юнита в узел (башня с темпом → 1:1 → захват), касания 1:1 на дорогах (swept). Сила юнитов удалена из боя, касаний, ИИ и превью (`unitStrengthMult` убрать из `SideModifiers`; бонус в `Progress` оставить в сохранении). Старые `ArmyState` и разовый урон башни удалены. Тесты из `ARCHITECTURE.md` → «Тесты».
- **Готово, когда:** все правила GDD §3.6 покрыты тестами; `npm run bench` укладывается в бюджет `ARCHITECTURE.md` → «Производительность».

**P-2. Рендер и производительность.** `UnitsView` (пул, одна текстура, интерполяция), `ArmyView` удалён. Вспышки касаний и выстрелы башни с потолком, звук с ограничением частоты. Dev-уровень `dev_stress` и счётчик FPS под dev-флагом.
- **Готово, когда:** `dev_stress` держит 60 FPS при CPU throttling ×6; в портрете 360×640 колонна читается (юниты не сливаются в линию и не перекрывают узлы).

**P-3. ИИ и совместимость.** ИИ учитывает, что отправка длится во времени: счётчики `incoming`, не делает повторный свайп из узла, который ещё выпускает поток, не пытается отправлять из атакованного узла; `pull` тоже потоком. Разбойники и цитадель выпускают потоком; порталы пропускают каждый юнит за 1 с; огненный шар, маг и дракон бьют только по гарнизону; щит — каждый юнит разбивается, узел не считается атакованным (TBD). Превью свайпа считает башню приблизительно (темп × время выпуска). Экран «Прокачка» скрывает бонус «Сила юнитов».
- **Готово, когда:** smoke-тест «ИИ против ИИ» по всем уровням и dev-уровням завершает бои; ИИ не «дёргает» потоки.

**P-4. Баланс.** Применить ×0.5 из `BALANCE.md` к `balance.ts` и ко всем JSON уровней (гарнизоны, стартовые войска; золото не трогать). Перепроверить инварианты обучения из `TUTORIAL.md` (например, ур. 1: гарнизон n2 больше 75% одного узла и меньше суммы двух). Прогнать `tests/levels.test.ts` и подогнать уровни главы 1 обратно в коридоры побед. Итог записать в `BALANCE.md` разделом «После потоков».
- **Готово, когда:** коридоры главы 1 из `BALANCE.md` выполняются; бои в среднем 1–1.5 мин; ручной плейтест главы 1 с чистого сохранения.

**P-5. Плотность и транзит.** Въезд на дорогу (шаг колонны — свойство полосы), очередь потоков одного узла на одну дорогу, транзит через свои узлы через гарнизон, повторный свайп отменяет всё, что выходит из узла, любой урон по гарнизону (огненный шар, маг, дракон) = атака, появление и приход у края круга (`STREAM.edgeDist`), рендер отображает отрезок между кругами.
- **Готово, когда:** тест — шаг между соседними юнитами на любой полосе никогда не меньше эталонного при частых свайпах, транзите, свайпе из нескольких узлов и волне цитадели; колонна выходит из-под круга без задержки в портрете и альбоме.
