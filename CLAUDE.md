# CLAUDE.md — инструкции для Claude Code

Название игры: **Tiny Kingdoms** (русское название в каталоге — TBD).
Казуальная стратегия «захват узлов» в духе Circle Empires / State.io для платформы **Яндекс Игры**.

Перед любой работой прочитай:
- `docs/GDD.md` — геймдизайн: что делает игра и по каким правилам.
- `docs/ARCHITECTURE.md` — как устроен код.
- `docs/BALANCE.md` — стартовые числа баланса (все настраиваемые).
- `docs/ROADMAP.md` — порядок разработки и критерии готовности этапов.
- `docs/UX.md` — план улучшений UX после MVP (этапы UX-1…UX-4).
- `docs/CONTENT.md` — план нового контента: особые узлы, лидеры врагов, цели уровней, боссы, второй враг (этапы C-1…C-5).
- `docs/TUTORIAL.md` — переработка обучения и открытие механик в главе 1 (этапы T-1…T-7): только свайп, замки на неизученном, замедление на шагах обучения, тур «Прокачки», злой маг. Делать строго по этапам.
- `docs/AUDIO.md` — музыка и звук: реестр треков с лицензиями и задачи на подключение (A-1…A-4).
- Армии-потоки (юниты выходят цепочкой, бой 1:1) — GDD §3.6, этап 9 в `docs/ROADMAP.md` (P-1…P-4), правила производительности — `docs/ARCHITECTURE.md` → «Производительность».
- `docs/PLAYTEST-1.md` — исправления по итогам плейтеста главы 1 (этапы F-1…F-8): меню при запуске, счётчик узла, захват построек, золото, открытие механик по применению, полная блокировка на уроках, сундук, карточка мага. Каждый этап — отдельный PR.
- `docs/VISUALS.md` — живые экраны: главное меню и карта глав (этапы V-1…V-4); новое главное меню со знамёнами — V-4, эталоны `docs/prototypes/menu-mobile-tournament.html` (портрет) и `docs/prototypes/menu-desktop-night.html` (альбом).
- `docs/PERF.md` — оптимизация рендера боя без изменения визуала (этапы PF-0…PF-6): сначала замер, счётчики узлов без `Text`, дуги без `Graphics.clear()`, аллокации в кадре, прогрев в BootScene. Каждый этап — отдельный коммит.

Если документы противоречат друг другу, приоритет такой: GDD > ARCHITECTURE > BALANCE. Если решения нет в документах — не выдумывай геймдизайн, а спроси или оставь `// TODO(design): ...`.

## Язык

- Общение, планы и объяснения — на русском.
- Код, имена переменных и комментарии в коде — на английском.
- Сообщения коммитов — на английском.

## Стек

| Что | Решение |
|---|---|
| Язык | TypeScript, `strict: true` |
| Движок | Phaser 4 (последняя стабильная 4.x на момент старта; проверь `npm view phaser version`) |
| Сборка | Vite |
| Тесты | Vitest — **только игровая логика** (симуляция, экономика, ИИ, сохранения). Рендер не тестируем |
| Платформа | Яндекс Игры, SDK v2 (`/sdk.js`) |
| Бэкенд | Нет. Сохранения — через SDK Яндекса + localStorage как запасной вариант |

## Команды

```bash
npm install
npm run dev        # dev-сервер Vite
npm run build      # продакшн-сборка в dist/
npm run test       # Vitest
npm run lint       # ESLint
npm run zip        # dist/ -> build.zip для загрузки в Консоль Яндекс Игр
npm run gen-level -- --seed 3 --nodes 8 --id c01_l06 --index 6   # черновик уровня по seed (JSON в stdout)
npm run bench      # бенчмарк симуляции: 600 юнитов, 10 000 тиков, бюджет ≤ 0.5 мс на тик
npm run profile    # замер рендера боя в headless Chrome/Edge, CPU ×6 (docs/PERF.md PF-0); -- --shots — эталонные скриншоты
```

## Жёсткие правила

1. **Логика отделена от рендера.** Всё в `src/core/` — чистый TypeScript без импорта Phaser, детерминированный, покрыт тестами. Phaser только рисует состояние и передаёт ввод.
2. **Все числа баланса — в `src/config/balance.ts`.** Никаких магических чисел в логике.
3. **Уровни — данные, а не код.** JSON в `src/levels/`, схема в `src/core/level/schema.ts`.
4. **Весь текст через i18n** (`src/i18n/ru.json`, `en.json`). Никаких строк в коде интерфейса.
5. **SDK Яндекса только через обёртку** `src/platform/` (интерфейс `Platform`). В dev-режиме используется `MockPlatform`, чтобы игра запускалась без SDK.
6. **Мобильные — приоритет.** Проверяй каждую сцену в портрете 360×640 и в альбоме 1280×720. Минимальный размер зоны касания — 48 px.
7. **Производительность.** Каждый юнит — отдельная фигурка, поэтому производительность — приоритет №1 боя: все юниты рисуются одним батчем из пула (одна текстура, без `Text`/`Graphics` на юнита, без создания объектов в бою), симуляция без аллокаций в горячем цикле. Цель — стабильные 60 FPS на слабом Android при 600 юнитах. Подробно — `docs/ARCHITECTURE.md` → «Производительность»; проверка — `npm run bench` и `dev_stress`.
8. **Размер билда** держи минимальным: графика рисуется кодом (Phaser Graphics/SVG), внешние ассеты — только при необходимости.
9. После каждого этапа: `npm run lint && npm run test && npm run build` должны проходить.

## Требования Яндекс Игр, которые легко забыть

- Вызвать `LoadingAPI.ready()`, когда игра загрузилась и готова к взаимодействию.
- Вызывать `GameplayAPI.start()` / `stop()` при начале/паузе геймплея.
- Во время рекламы и при скрытии вкладки — пауза игры и звука.
- Не показывать рекламу во время активного боя (только между уровнями).
- Игра не должна прокручивать страницу и выделять текст; контекстное меню и долгий тап отключены.
- Язык определяется из `ysdk.environment.i18n.lang` (ru → русский, всё остальное → английский).
- Покупки: на старте проверить необработанные покупки (`getPurchases`) и выдать их.

Перед реализацией интеграции сверяй имена методов с актуальной документацией: https://yandex.ru/dev/games/doc/ru/sdk
